# 商业化用 AI 提效：6 个代表场景

> 组内分享稿 · 2026.04–08 · 约 10 分钟讲完  
> 只讲「工作里怎么用 AI」，不讲「产品里怎么卖 AI」

---

## 开场（30 秒）

这 5 个月商业化不是「让 AI 写了几份文档」，而是把它嵌进整条工作链：

**看清市场 → 做出判断 → 写成可研发交付 → 画成可评审 / 可汇报 → 沉淀成可复用能力。**

下面 6 个案例，每个只讲四件事：**当时卡在哪、AI 干了啥、人拍了啥板、组内能直接复用什么。**

---

## 1. 全球母婴订阅调研：从「感觉对标」到「能拍板的一手报告」

**卡在哪**  
订阅 9 月要上，定价、转化目标、付费墙形态都缺行业锚点。公开资料散、口径乱，飞书表导出还缺表。

**AI 干了啥**  
按「卖什么 / 怎么卖 / 何时触发 / 如何留存 / 我们怎么做」五问收口；把 15 个对象拆成三批深浅；价格、财报、实测交叉核对，并标 ✅ / ⚠️ / 🔲；最后收成管理层可读的 MD + HTML。

**人拍了啥板**  
哪些必须买会员实测、哪些只体验触点；不把推算写成结论；Momcozy 订阅率目标用 Owlet / Nanit 的 20%–28% 作参照，落到 **10%–20%**；定价锚在 **$8.99–$14.99**。

**用过的 Skill**  
`html-ppt`（调研报告 HTML / 汇总页）· `editorial-poster`（Paywall 案例库海报）

**可复用**  
调研先定五问，再找对象；数字必须带来源等级。报告在 `docs/全球母婴市场订阅付费调研报告.md`。

**一句话结论**  
硬件绑定转化 20%–28%，纯软 3%–8%；Medela / Willow / Elvie 软件订阅收入为 $0，吸奶器线不能和摄像头线用同一套价。

## 2. 2026 规划 + LTV 纠偏：AI 帮成稿，人也要敢改自己的优先级

**卡在哪**  
Q2 要同时讲清：一次性购买、订阅、商城怎么排；到了 7 月，材料齐了，但「订阅当主线」可能排错了。

**AI 干了啥**  
5 月：把节奏、依赖、HC、风险收成「完整版 + 高管摘要」，甘特和决策请求写清楚。  
7 月：把规划、调研、ARR、DTC 交叉对照，算出 LTV 六项弹性完全不同，提出优先级反转。

**人拍了啥板**  
5 月拍的是节奏：6 月一次性购买、9 月订阅、商城分 V1/V2/V3。  
7 月拍的是方向：软件订阅更像硬件卖点和留存钩子；耗材 Autoship 的 LTV 贡献约是订阅的 2 倍，且不吃 30% 渠道抽成。方案已提交，决策仍在讨论——**纠偏本身也是产出**。

**用过的 Skill**  
`product-design-workflow`（全年甘特 / 依赖图）· 规划与 LTV 正文为对话成稿，未走专用 Skill

**可复用**  
规划用 AI 成稿没问题；过两个月要用新材料回头打自己。文档：`commercialization planning/` 与 `docs/momcozy-用户数字化商业化与LTV提升方案.md`。

## 3. 摄像头 / BBM ARR：把「能卖多少」拆成可改假设的公式

**卡在哪**  
管理层要 ARR，但双档（Plus / Premium）× 双周期（月 / 年）混在一起，改一个假设全盘重算，也说不清净收入。

**AI 干了啥**  
写成可套数字的公式：激活设备 → 试用转付费 → 档位 / 周期结构 → 续费率 → 扣渠道抽成和云成本 = 净 ARR。补了 8 个指标定义、中性预期表、付费转化路径（试用期价值外显、Paywall 触达）。

**人拍了啥板**  
哪些是内部真实数、哪些是行业假设；续费率是灵魂指标（高则滚雪球，低则 MRR 走平）；摄像头线可以按竞品转化谈，吸奶器线不行。

**用过的 Skill**  
`editorial-poster`（ARR / BBM 三页汇报 HTML）· 公式正文为对话成稿

**可复用**  
测算先锁公式和假设表，再填数。文档：`docs/Baby摄像头订阅ARR测算与付费路径.md`。

## 4. PayHub / RevenueCat 双 PRD + 流程图：从「接入一个 SDK」变成可开发的中台

**卡在哪**  
要在 App 里收钱：课程一次性购买 + 存储 / 订阅。范围一混，研发、法务、QA 对不齐；Webhook、权益、退款、跨端掉单任何一环说不清都会返工。

**AI 干了啥**  
拆成 PRD-1（课程 IAP，6 月上线）和 PRD-2（存储订阅，9 月）；统一术语（Entitlement / Offering / Webhook）；按同一设计系统出流程图（购买、权益判断、生命周期、Linkout、Webhook）。后面补了开发前配置清单和隐私披露口径。

**人拍了啥板**  
MVP 砍什么（购买记录查询可后置）；课程权益仍走现有后端，订阅权益以 RevenueCat 为准；暂不用 RC 的 Targeting / 营销推送，避免多走一轮合规。

**用过的 Skill**  
`product-design-workflow`（PRD-1 / PRD-2 + 11 张 drawio：购买、权益、生命周期、Webhook、甘特）

**可复用**  
复杂接入先拆阶段，再出 PRD + 图，不要一份大而全。文档：`docs/PRD-1-*.md`、`docs/PRD-2-*.md`、`docs/flowcharts/`。

## 5. 订阅底座架构图：一张图讲清「卖什么 / 怎么上 / 在哪触发」

**卡在哪**  
IoT、AI、婴儿床、课程各给一截付费点，评审时对不上。需要一张图：供给侧矩阵 + 中台怎么快速上 SKU。

**AI 干了啥**  
先出 6 层骨架再填肉：付费能力矩阵 → 订阅中台准入 → Paywall 入口 → 触达 → 指标 → 运营。AI / BBM 用真实清单，婴儿床 / 白噪音 / 课程用行业参考并标「待确认」。同步 HTML 和 drawio。

**人拍了啥板**  
中台不是「所有功能都能卖」，要先过用户价值验证再接；Paywall 入口分推荐 / 谨慎；新产线先验证、再品牌归一。

**用过的 Skill**  
当时按仓库原型规范**手写 HTML**，未走 `archify` / `architecture-diagram`。同类任务下次应先调这两个。

**可复用**  
架构图先对骨架，确认后再铺功能。图：`momcozy-订阅付费商业化底座架构图.html`。

## 6. Skill / SOP / 面试手册：把一次提效变成团队能接着用的流程

**卡在哪**  
前面 5 类如果每次从零聊天，人一换、场景一换就重来。订阅配置跨 Apple / Google / RC 三端，顺序错了要返工一整天。招人没有统一题和打分。

**AI 干了啥**  
把反复跑通的路径写成 Skill（PRD → 流程图 → 原型）；把配置写成 9 步 SOP，每步有字段、坑和 Gate；把 EC / VAS 面试收成 60 分钟手册 + 7 维画像。协作习惯也固化了：**先框架、确认后再细写。**

**人拍了啥板**  
Skill 不替代评审；SOP 里账号、定价、法务仍是人；面试手册是辅助判断，录用决定在面试官。

**用过的 Skill**  
沉淀物本身就是 Skill：`product-design-workflow`（PRD→图→原型）· 本分享页用 `editorial-poster`

**可复用**  
同类任务跑通第二次，就该沉淀。SOP：`docs/付费订阅产品配置SOP.md`；面试：`docs/PM面试评估手册.md`。

---

## 组内可带走的 3 条

1. **先框架后细节。** 规划、架构、调研都是「骨架确认再铺肉」，比一次生成 50 页返工更少。
2. **AI 负责结构、交叉和成稿；人负责口径、取舍和纠偏。** 调研的来源等级、PRD 的砍范围、LTV 的优先级反转，都不是模型能替你签字的。
3. **提效要写进下一次。** 能复用的不是那次对话，是 PRD 框架、SOP、Skill 和「数字必须带来源」这种约定。

## 附录：产出用过的 Skill（下次直接唤）

同类任务不必从零描述格式，把 Skill 名字说出来即可。

| Skill | 干什么 | 唤法 | 这 5 个月落到哪 |
|---|---|---|---|
| **html-ppt** | 可翻页 / 长文 HTML 汇报稿 | 「用 html-ppt 做一份调研汇报」 | 全球母婴订阅调研报告 HTML |
| **editorial-poster** | 暗刊风单页海报（KPI 裸奔、杂志排版） | 「用杂志风 / editorial-poster 出一页」 | Paywall 案例库、ARR 三页、**本分享页** |
| **product-design-workflow** | PRD → drawio 流程图 → 原型 | 「走完整产品设计流程」或「写 PRD + 出流程图」 | PayHub 双 PRD、11 张流程图、规划甘特 |
| **archify** | 架构 / 流程 / 状态机 HTML+SVG，带明暗切换 | 「用 archify 画架构图」 | 底座图当时手写；**下次架构图用它** |
| **Cursor Canvas** | 数据密集分析画布 | 「做成 Canvas」 | 同期产康竞品分析（未进 6 案主线） |

**用法约定（组内可抄）**

1. 先说产出形态（报告 / PRD / 图 / 海报），再点 Skill 名。  
2. 没有对应 Skill 就对话成稿，跑通第二次再沉淀，不要硬套。  
3. Skill 管结构和版式，口径、砍范围、是否上线仍是人签。
